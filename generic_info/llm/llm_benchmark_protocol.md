# LLM Chess Benchmark Protocol

This benchmark compares frozen GNN chess-puzzle models with local LLMs served by Ollama.

No official benchmark is executed during framework implementation.

## Protocol A: Next-Move Prediction

Input to the LLM:

- FEN only
- canonical instruction
- required output format

The LLM does not receive TargetMove, solution moves, MateDepth, rating, themes, legal moves, A3 candidates, A4 scores, Stockfish output, or future states.

Metric:

- Top-1 exact legal UCI move accuracy against the canonical Lichess target.

This is the direct comparison with A3/A4 Top-1.

## Protocol B: Reference-Line Puzzle Solving

For each solver turn:

1. Send the current FEN to the LLM.
2. Parse one UCI move.
3. Validate legality with python-chess.
4. Compare with the canonical Lichess solver move.
5. If correct, apply it.
6. Apply the canonical Lichess opponent reply.
7. Continue until solved or first failure.

Opponent replies are never generated by the LLM.

## Mate-in-N Semantics

Mate-in-N means N moves by the solving side, not N total plies. A Mate-in-4 line may contain up to 7 plies.

## Top-K Fairness

LLMs produce one move in the primary benchmark. Do not report LLM Top-3/Top-5 from a single generated response.
